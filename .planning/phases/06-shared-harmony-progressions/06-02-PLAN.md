# Phase 6, Plan 02: The strict harmony gate, in place before any more progressions are committed

## Phase Goal

**As a** rider, **I want to** hear the music move through chord progressions that bass, arp and pad follow together, **so that** it stops sounding like the same few notes for an hour.

Committed library files can never be edited, so every check that could catch a bad progression must exist before the next six files are committed (Plan 03). This plan pins the harmony rules with exact expected values (the tables in Plan 01), adds a strict branch to the static tier that renders two full cycles of every chord-data file, refuses malformed chord data with exact reasons, and turns the anthem recording into a loop over every progression on disk, so a new file is covered automatically.

<objective>
Make `./scripts/check.sh --library-only` prove, for anthem today and for every progression file added later, that all pitched notes stay in their bar's chord, the pad takes the nearest voicing inside 40-64 and holds it, the bass and arp follow the agreed tables, classic is untouched, and malformed chord data is refused.

Purpose: HARM-01 and HARM-03 proofs, including the two HARM-03 edge truths from the spec-less probe. Implements the RESEARCH Validation Architecture Wave 0 items (pure function checks, chord-follow tier, negative controls) and Open Question 5: a cycle longer than 8 bars prints a `CHECK WARN` line and does not fail.
Output: modified `supercollider/library_test.scd` and `scripts/check.sh`. No engine or library file changes; if a check exposes a core defect, fix it in `supercollider/core/` and say so in the SUMMARY.
</objective>
