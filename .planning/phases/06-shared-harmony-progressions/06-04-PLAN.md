# Phase 6, Plan 04: On Auto the engine moves through the progressions by itself

## Phase Goal

**As a** rider, **I want to** hear the music move through chord progressions that bass, arp and pad follow together, **so that** it stops sounding like the same few notes for an hour.

The app sends `auto` for all three selectors at launch, so Auto is what the rider hears by default. This plan makes Auto real for progressions: classic first, then a new progression every 2-3 minutes, always at the end of a cycle, chosen by a seeded shuffle with no quick repeats, including any file added while the engine runs. It plugs into the single decision point Plan 01 built (`~ppHarmDecide`), so named picks and Auto share one cycle-end rule.

<objective>
Implement Auto rotation for progressions (D-08, D-09, D-10, D-11) at the existing cycle decision, with a background prefetch so every progression file on disk is a candidate, and prove rotation, adoption, new-file pickup, failure handling and bounded state in the library check.

Purpose: HARM-04 (Auto half) and HARM-02 ("On Auto, the engine chooses progressions on its own").
Output: modified harmony.scd, loader.scd, main.scd and library_test.scd. No Python change.

Resolutions recorded here (RESEARCH open questions, CONTEXT discretion):
- Auto seed (Open Question 3): `~ppAutoSeed = ~ppAutoSeed ? (Date.getDate.rawSeconds % 1000000).asInteger`, chosen once per interpreter, kept across re-evaluation, posted at every evaluation of main.scd; tests set it. Every Auto draw seeds the thread from (seed, pick number) right before it; generators re-seed their own thread, so nothing leaks.
- Returning to Auto mid-run (Open Question 4): Auto adopts the progression that is playing and holds it for a fresh hold, then shuffles. After a Start, Auto always begins on classic (D-09, RESEARCH A6: Stop/Start restarts the song).
- Hold (D-08): H = max(1, round(rrand(lo, hi) / cycleLen)) whole cycles with [lo, hi] = ~ppAutoHoldBars, default [32, 64]; tests shrink it.
- Candidates (D-10): stems in the registry that pass ~ppStemValid, whose file exists in the current library root, and whose render-error count is below 3, sorted by name before the seeded choice (Dictionary order is not stable). Remove the current stem and the last two of the history; if nothing is left use all candidates but the current; if still nothing, keep the current.
</objective>
