# Phase 5, Plan 01: Pick any library variation from the window

## Phase Goal

**As a** rider, **I want to** have Palette, Progression and Melody selectors in the PedalPulse window, **so that** I can pick Auto or any named variation using the same names I use when giving feedback.

This plan is the tracer for the phase. Task 1 wires one dropdown (Melody) through every layer the phase touches: the folder scan, a selector controller, a new OSC send, the Tk view and the app's startup wiring. Its proof is a real end-to-end test: a pick in the real Tk menu arrives as an OSC datagram on a bound loopback socket. Task 2 then adds Palette and Progression and pins the layout and the launch-time sends at the real entry point. The engine side already exists from Phase 4 (`~ppSelect` posts a line for every outcome), so this phase changes no engine file.

<objective>
Add a right-hand column of three `tk.OptionMenu` dropdowns (Palette, Progression, Melody) to `BpmWindow`. Each lists `Auto` plus the file stems in its `supercollider/library/<folder>/`, and sends the picked name to `/pp/palette`, `/pp/progression` or `/pp/melody` only when the choice changes. The app sends `auto` to all three at launch.

Purpose: GUI-05 (selectors listing Auto plus the files on disk) and GUI-06 (the selection reaches the engine over send-only OSC, by name). Implements D-01, D-02, D-03, D-04, D-05, D-06 and D-07. Plan 05-02 tightens the folder scan to the engine's exact name rule and proves the controller and send contracts. Plan 05-03 adds rescan on open (D-08) and the GUI-07 keyboard proof.
Output: new `python_app/library_logic.py` and `python_app/tests/test_main_launch.py`; modified `config.py`, `osc_client.py`, `view.py`, `main.py` and `tests/test_view_tk.py`.
</objective>
