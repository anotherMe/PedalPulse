# Phase 4, Plan 03: A broken file never stops the music

## Phase Goal

**As a** rider, **I want to** have the engine split into a core plus a library of named variation files, with no change to what I hear, **so that** new variations can be added as files and switched to without ever stopping the music.

New variations are written by Claude between rides and tried during a ride, so a mistake in one file must never cost the rider the music. This plan adds validation of every file, refusal with an error that names the file, a last-good-copy rule, and a per-bar fallback to classic. A file that loads but misbehaves while playing degrades to the classic part instead of going silent. It also closes the remaining research checks: seeding, and bar timing across a tempo change.

<objective>
Create `supercollider/core/validate.scd`. Wire validation into the loader, and add per-bar containment and seeding to the renderer. Prove every refusal, reload and fallback path with fixtures in a temporary library root inside `supercollider/library_test.scd`; fixtures never go in `supercollider/library/`.

Purpose: LIB-04 (a broken or invalid file never stops the music; error logged; keep or fall back to classic), LIB-05 (add or change a file while running), and the validation half of LIB-06. Implements the Claude's-discretion defaults in CONTEXT: last good copy, otherwise classic; selecting a name re-reads it; invalid names are ignored with a warning.
Output: new `core/validate.scd`; modified `core/loader.scd`, `core/render.scd`, `main.scd` and `library_test.scd`.
</objective>

1. supercollider/core/validate.scd (new). Pure and server-free: it only defines ~ variables, and its last expression is non-nil. Define:
   - ~ppDrumRoles = [\kick, \hat, \clap] and ~ppPitchedRoles = [\bass, \pad, \arp, \lead].
   - ~ppRowsValid.(rows): returns nil when valid, otherwise one reason String. Valid means:
     - rows is an Array with at least one row, and every row is an Array of 4 items;
     - note is \rest, a finite Number, or a non-empty Array of finite Numbers;
     - dur is a finite Number > 0; amp is a finite Number from 0 to 1; legato is a finite Number > 0;
     - the durs sum to 4.0 within 1e-6.
     Example reasons: "bar fills 3.5 beats, not 4" and "row 3 is not [note, dur, amp, legato]".
   - ~ppValidate.(cat, module): returns an Array of reason Strings (empty means valid).
     - Every category: module is an Event, and module[\desc] is a non-empty String.
     - \progressions: \bass and \pad are Functions when present, and at least one is present.
     - \melodies: \arp and \lead are Functions when present, and at least one is present; \init, when present, is a Function.
     - \palettes: \roles is an Event with at least one known role (drum or pitched); every known role maps to an Event whose \instrument is a Symbol; \defs, when present, is a Function.
     Unknown keys and unknown role names are ignored, never errors. This is the contract-freeze rule: later phases add optional fields, and committed files never need an edit.
   - ~ppValidateVoices.(module): returns reasons for a palette's voices. For every known role, SynthDescLib.global.at(instrument) must exist and its controls must include out and amp, plus freq and gate for pitched roles. This only works after defs has run (client-side, no server needed).
