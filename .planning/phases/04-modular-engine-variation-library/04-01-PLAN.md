# Phase 4, Plan 01: The groove now comes from the library, proven note for note

## Phase Goal

**As a** rider, **I want to** have the engine split into a core plus a library of named variation files, with no change to what I hear, **so that** new variations can be added as files and switched to without ever stopping the music.

This plan is the tracer for the whole phase. It first records what the shipped engine plays (the golden), then moves the music out of `main.scd` into three `classic` library files, read by a new loader and played by a new per-bar renderer. A note-level parity check proves nothing changed. The plan ends with the one command, `scripts/check.sh`, that every later plan uses as its gate. That command also protects every committed library file from being edited.

<objective>
Record the shipped groove from the unmodified engine (`supercollider/golden/shipped_groove.scd`) with a new test harness (`supercollider/library_test.scd`). Then route every layer through `supercollider/core/loader.scd` and `supercollider/core/render.scd`, with the musical content in `supercollider/library/{progressions,melodies,palettes}/classic.scd`. Finally add `scripts/check.sh`: never-overwrite guard (with self-test), library check, smoke suite.

Purpose: LIB-01 (start exactly as before, sounds the same), LIB-02 (each variation is a named file), LIB-03 (guard), LIB-06 (the check runs with the smoke suite from one command). Implements D-01 (automated half of the parity proof), D-02 (effective amps reproduced, not fixed), D-03 (existing smoke checks unchanged) and D-07 (startup defaults to classic).
Output: 7 new files, a generated golden, and a modified `supercollider/main.scd`.

Working decisions this plan implements (RESEARCH recommendations adopted; orchestrator resolutions of the RESEARCH open questions):
- Category keys are the folder names `\progressions`, `\melodies`, `\palettes`, used as keys everywhere (`~ppLib`, `~ppSel`, `~ppLibEnsure`). The OSC addresses (Plan 02) stay singular: `/pp/progression`, `/pp/melody`, `/pp/palette`.
- One new script: `scripts/check.sh`, with a `--library-only` fast loop. There is no separate `library_check.sh` and no `pp_select.sh`, so the user has fewer scripts to know. `scripts/smoke_test.sh` stays unchanged.
- The guard is strict. There is no edit override: if the listening check asks for a different `classic_lead` level, the change lands as a new library file (Plan 05). The guard also protects the golden, so a re-recorded golden can never quietly make the parity check meaningless.
- The golden file is `supercollider/golden/shipped_groove.scd`. This plan's paths are authoritative over the seeded `04-VALIDATION.md`.
</objective>
