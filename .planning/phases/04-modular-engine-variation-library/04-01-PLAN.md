# Phase 4, Plan 01: Freeze what the shipped engine plays, and one command that guards it

## Phase Goal

**As a** rider, **I want to** have the engine split into a core plus a library of named variation files, with no change to what I hear, **so that** new variations can be added as files and switched to without ever stopping the music.

Before anything in the engine moves, this plan records exactly what the shipped engine plays (the golden) and proves, on that same unmodified engine, that the note-level parity check passes. It then adds the one command, `scripts/check.sh`, that every later plan uses as its gate. That command also protects every committed library file and the golden from being edited. No engine file changes in this plan. It runs before the phase's tracer (Plan 02 Task 1) because D-01 requires the golden to come from the unmodified engine.

<objective>
Record the shipped groove from the unmodified engine (`supercollider/golden/shipped_groove.scd`) with a new test harness (`supercollider/library_test.scd`), and prove the parity check passes against that same engine. Then add `scripts/check.sh`: never-overwrite guard (with self-test), library check, smoke suite.

Purpose: the automated half of the LIB-01 proof (the golden and the parity check that Plan 02 must pass), LIB-03 (guard), LIB-06 (the library check runs with the smoke suite from one command). Implements D-01 (golden recorded before the split), D-02 (effective amps captured as they are, not fixed) and D-03 (existing smoke checks unchanged).
Output: 2 new files and a generated golden. No engine file changes.

Working decisions this plan implements (RESEARCH recommendations adopted; orchestrator resolutions of the RESEARCH open questions):
- One new script: `scripts/check.sh`, with a `--library-only` fast loop. There is no separate `library_check.sh` and no `pp_select.sh`, so the user has fewer scripts to know. `scripts/smoke_test.sh` stays unchanged.
- The guard is strict. There is no edit override: if the listening check asks for a different `classic_lead` level, the change lands as a new library file (Plan 06). The guard also protects the golden, so a re-recorded golden can never quietly make the parity check meaningless.
- The golden file is `supercollider/golden/shipped_groove.scd`. This plan's paths are authoritative over the seeded `04-VALIDATION.md`.
</objective>
