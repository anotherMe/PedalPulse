# Phase 4, Plan 02: The groove now comes from the library, proven note for note

## Phase Goal

**As a** rider, **I want to** have the engine split into a core plus a library of named variation files, with no change to what I hear, **so that** new variations can be added as files and switched to without ever stopping the music.

This plan is the tracer for the whole phase. It moves the music out of `main.scd` into three `classic` library files, read by a new loader and played by a new per-bar renderer. The golden and the note-level parity check that Plan 01 recorded from the unmodified engine prove nothing changed, and `bash scripts/check.sh` (also from Plan 01) is the gate for both tasks. From here on, the guard in that command protects every committed library file from being edited.

<objective>
Route every layer through `supercollider/core/loader.scd` and `supercollider/core/render.scd`, with the musical content in `supercollider/library/{progressions,melodies,palettes}/classic.scd`. Prove it with Plan 01's parity check (0 mismatches against `supercollider/golden/shipped_groove.scd`) and the unchanged smoke suite, both run by `bash scripts/check.sh`.

Purpose: LIB-01 (start exactly as before, sounds the same), LIB-02 (each variation is a named file). Implements D-01 (the split passes the automated half of the parity proof), D-02 (effective amps reproduced, not fixed), D-03 (existing smoke checks unchanged) and D-07 (startup defaults to classic).
Output: 5 new files and a modified `supercollider/main.scd`.

Working decisions this plan implements (RESEARCH recommendations adopted; orchestrator resolutions of the RESEARCH open questions):
- Category keys are the folder names `\progressions`, `\melodies`, `\palettes`, used as keys everywhere (`~ppLib`, `~ppSel`, `~ppLibEnsure`). The OSC addresses (Plan 03) stay singular: `/pp/progression`, `/pp/melody`, `/pp/palette`.
- The golden, `supercollider/library_test.scd` and `scripts/check.sh` come from Plan 01 and are not changed here. If parity fails, the engine side is wrong, never the reference.
- The guard from Plan 01 is strict, with no edit override, so every classic file is final when first committed. A later change of sound (for example a different `classic_lead` level after the Plan 06 listening check) lands as a new library file.
</objective>

Use [\key] access on Events everywhere, never dot syntax: dot syntax collides with Object methods such as name and size. Define:
   - ~ppLibCategories = [\progressions, \melodies, \palettes].
   - ~ppLog = { |line| ... }: post the line, append it to ~ppLogLines (a List trimmed to the last 100 entries) and return it.
   - ~ppLib = ~ppLib ? (progressions: (), melodies: (), palettes: ()), so re-evaluating this module alone never drops loaded modules.
   - ~ppLibPath.(cat, stem) = ~ppLibRoot +/+ cat.asString +/+ (stem.asString ++ ".scd").
   - ~ppLibLoad.(cat, stem): log `PedalPulse: loading <path>`. String:load compile errors do not name the file (Pitfall 2), so the loader always does.
