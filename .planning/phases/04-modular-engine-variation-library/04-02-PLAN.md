# Phase 4, Plan 02: Pick a variation by name while the music plays

## Phase Goal

**As a** rider, **I want to** have the engine split into a core plus a library of named variation files, with no change to what I hear, **so that** new variations can be added as files and switched to without ever stopping the music.

After Plan 01 the music comes from library files, but only `classic` exists and nothing can switch it. This plan adds the 7th layer (the lead), the first non-classic file `classic_lead`, and the three selection addresses. Phase 5's GUI will use the same addresses. The rider can now send `/pp/melody classic_lead` and hear a faint shimmer from the next bar, then send `/pp/melody classic` to get the shipped sound back.

<objective>
Add `\ppLead` as the 7th layer (D-04) and `supercollider/library/melodies/classic_lead.scd` (D-06). Add `/pp/progression`, `/pp/palette` and `/pp/melody` handlers that validate the name, load the file in a background Routine and switch on the next bar line. Then prove all of it in a selection tier of `supercollider/library_test.scd`.

Purpose: LIB-05 (select or reload by name without restart or gap) and LIB-02 (the file stem is the name over OSC). Implements D-04, D-05, D-06 and D-07; keeps D-03 (smoke changes only by the 7th layer in the expected set).
Output: modified `main.scd`, `core/loader.scd`, `core/render.scd`, `smoke_test.scd`, `library_test.scd`; new `library/melodies/classic_lead.scd`.

Frozen interface for Phase 5 (do not change later): three loopback-only addresses, each with one string argument, `auto` or a stem. A stem is 1-64 characters from a-z, 0-9 and _, does not start with _, and is not `auto`. An unknown or invalid name gets a post-window warning and leaves the music unchanged. No reply is ever sent. Re-sending the current name reloads the file. `auto` is stored as `\auto` and resolves to `classic` through `~ppResolveStem` (RESEARCH open question 3).
</objective>
