# Phase 3, Plan 02: Five zone buttons in the app

## Phase Goal

**As a** rider, **I want to** pick my effort zone and set the volume, **so that** the music's energy matches my interval without clipping.

After Plan 01 the engine reacts to `/pp/epic` sent from a terminal. This plan puts that control in the rider's hands: five zone buttons in the window, each sending its preset EPIC value through the client Plan 01 built, with the selected zone clearly shown. It closes EPIC-03 and is where the rider first hears the zones by ear. Before adding these controls it fixes the Phase 1 arrow-key finding, as STATE.md asks.

<objective>
Add the zone preset map to `python_app/config.py`, an `EpicController` to `python_app/bpm_logic.py` (test-first), and a zone button row to `python_app/view.py`. Wire the controller to `OscClient.send_epic` in `python_app/main.py`. Fix Phase 1 review WR-01: arrow keys must not nudge BPM while the entry has focus.

Purpose: EPIC-03 (select EPIC via five zone preset buttons, each mapped to a predefined value) and the rider-facing half of EPIC-01/02, judged by ear in the human check.
Output: updated `python_app/config.py`, `python_app/bpm_logic.py`, `python_app/view.py`, `python_app/main.py`, `python_app/tests/test_view_tk.py`; new `python_app/tests/test_epic_logic.py`.

Working decisions this plan implements (RESEARCH "Gray Areas" defaults adopted as working decisions; no CONTEXT.md exists for Phase 3):
- Zone values Recovery 10, Endurance 30, Tempo 50, Threshold 75, VO2 100; default zone Recovery. The engine never learns zone names; it only receives the number (RESEARCH Pattern 3). Reversible: a dict literal.
- `EpicController` is a new sibling class shaped like `PlayController` (discrete click, no debounce, notify only on a real change, `send_initial` at launch), matching the Phase 2 precedent of sibling controllers.
- Five `tk.Button`s, not Radiobuttons, to match the window's existing button language. **Planner deviation from RESEARCH:** RESEARCH highlights the selected zone with `relief` only. This Mac's Tk 9.0.3 reports windowing system `aqua` (checked during planning), where native buttons generally ignore `relief`, and the Phase 2 UI review already found no visible pressed state on macOS buttons. So the selected button also switches to a bold font copy, and a caption "Zone: <name>" under the row names the zone in plain text, which renders on any theme. During planning the bold weight was confirmed to be set and readable back through `tkinter.font`. The human check confirms the highlight is actually visible.
- WR-01 fix: the entry gets its own bindings for the four arrow sequences that return "break". This is the review's suggested fix. Verified during planning on this Tk build: key events go to the focus widget, and an entry-level "break" stops the root-level nudge binding.
- Phase 2 UI review spacing: new rows use `pady=8`, and `transport_row` moves from 4 to 8 so every control row shares one spacing value.
