# Phase 3, Plan 04: Volume slider in the app, and the phase acceptance listen

## Phase Goal

**As a** rider, **I want to** pick my effort zone and set the volume, **so that** the music's energy matches my interval without clipping.

Plan 03 made the engine respond to `/pp/volume` and proved VO2 at full volume never clips. This plan gives the rider the control: a Volume slider in the window that follows the drag live and sends once on release, exactly like the BPM slider. It closes GUI-03 and runs the end-of-phase listening acceptance for the whole phase through the real app.

<objective>
Add the volume range and default to `python_app/config.py`, a `clamp_volume` function and a `VolumeController` to `python_app/bpm_logic.py` (test-first), and a Volume `Scale` row to `python_app/view.py`. Wire the controller to `OscClient.send_volume` in `python_app/main.py`.

Purpose: GUI-03 (user can adjust master volume from the GUI), plus the end-of-phase confirmation by ear of ROADMAP Phase 3 success criteria 2-4.
Output: updated `python_app/config.py`, `python_app/bpm_logic.py`, `python_app/view.py`, `python_app/main.py`, `python_app/tests/test_view_tk.py`; new `python_app/tests/test_volume_logic.py`.

Working decisions this plan implements (RESEARCH "Gray Areas" defaults adopted as working decisions; no CONTEXT.md exists for Phase 3):
- The volume is a 0-100 integer in the GUI, default 80, sent as a float. The engine owns the taper and the clamp (Plan 03).
- `VolumeController` is a new sibling class shaped like `BpmController`'s slider half: live update while dragging, one send on release, `send_initial` at launch. There are no nudge buttons and no entry field (GUI-03 asks only to adjust master volume). `clamp_volume` copies `clamp_bpm`'s half-up-then-clamp contract instead of generalising it (RESEARCH Gray Areas: sibling over refactor, Phase 2 precedent).
- A horizontal `tk.Scale` labelled "Volume", 320 px like the BPM slider, `takefocus=0`. The Scale's built-in value readout shows the number, the same way the BPM slider does.
- Layout: the volume row goes after the transport row and before the status line, with `pady=8` like the other control rows (RESEARCH Gray Areas layout row; Plan 02 set every control row to 8).
</objective>
