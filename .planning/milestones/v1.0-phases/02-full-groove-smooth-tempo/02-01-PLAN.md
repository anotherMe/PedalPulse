# Phase 2, Plan 01: Start/Stop transport, end to end (tracer)

## Phase Goal

**As a** rider, **I want to** start, stop and retempo a full trance groove from the app, **so that** tempo changes never jolt my ride.

This plan proves the one new path that crosses every layer of the system: Python sends `/pp/play`, sclang validates it, and the engine stops or restarts the groove on the bar. The first task wires that path end to end through the real Python client. The second task makes Stop clean (no hanging notes, no pops) and the transport safe (idempotent, validated, loopback-only), after first proving RESEARCH Assumption A3. Plan 02 puts a Start/Stop button on this exact client; Plans 03 and 04 add the tempo glide and the full groove on top of `~ppStart`/`~ppStop`.

<objective>
Add the `/pp/play <int>` transport: `config.OSC_PLAY_ADDRESS`, `OscClient.send_play` plus a `--play` CLI option, and in `supercollider/main.scd` a layer list (`~ppLayers`), `~ppStart`/`~ppStop` functions and a validated, loopback-only, idempotent `OSCdef(\pp_play)`. Stop releases every sounding voice through a group-wide `\gate, 0` broadcast. Extend the headless smoke test so each behaviour is checked through the real engine.

Purpose: GUI-02 (start and stop the music from the GUI) needs an engine command first; this is the tracer slice that proves Python → OSC → sclang → patterns for the new message, the way Phase 1's tracer proved `/pp/bpm`.
Output: updated `python_app/config.py`, `python_app/osc_client.py`, `python_app/tests/test_osc_client.py`, `supercollider/main.scd`, `supercollider/smoke_test.scd`.

Working decisions this plan implements (no CONTEXT.md exists for Phase 2; these are the RESEARCH "Gray Areas" defaults, adopted as working decisions):
- Transport message is `/pp/play <int>`, 1 = start, 0 = stop, per Phase 1 D-19's `/pp/*` naming (rated costly, see Task 1).
- Stop is immediate: stop scheduling, then broadcast `\gate, 0` to the instrument group. No wait for the end of the bar.
- Start restarts at `quant: 4` (next bar line). **Planner deviation from RESEARCH:** `doReset: true`, not the default `false`. With `false`, a layer whose cycle is longer than one event (the bass's bar-end note change, the arp's 4-note cycle, Plan 04's pad progression) resumes mid-cycle at the bar line, so the groove would re-enter out of phase. Resetting every layer to its first event is what "brings the full groove back in time" requires. Reversible: one keyword argument.
- The engine still autostarts on boot (Phase 1 D-15); `~ppPlaying` starts true.
</objective>
