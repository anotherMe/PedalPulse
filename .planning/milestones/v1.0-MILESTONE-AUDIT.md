## Integration (gsd-integration-checker)

- **OSC routes:** 4/4 connected (`/pp/bpm` float, `/pp/play` int, `/pp/epic` float, `/pp/volume` float). Host and port agree at 127.0.0.1:57120. No orphaned senders or handlers.
- **Signal chain:** layers → mix bus → `\ppFx` (EPIC) → `\ppMaster` (volume → Limiter) → out. EPIC and volume both sit before the limiter.
- **Re-evaluation:** OSCdefs, SynthDefs and Pbindefs are keyed and replaced, not stacked.
- **Stop/Start:** BPM, EPIC and volume are all kept. A BPM change while stopped still glides.
- **Launch sync:** the app's initial values (120 / Recovery 10 / 80) match the engine's defaults.
- **pytest:** 150 passed (re-run in this audit). The headless SC smoke test was not re-run here because it boots a second sclang. Phase verification re-ran it green (65 checks in Phase 3).

### E2E flows: 6/6 complete
1. Launch → initial sends → the groove plays
2. BPM slider release → glide over 8 beats that retargets mid-glide
3. Nudge buttons, arrow keys and entry → debounced send
4. Start/Stop toggle → `~ppStart`/`~ppStop`
5. Zone button → `/pp/epic` → lagged `\ppFx`
6. Volume release → `/pp/volume` → lagged gain before the limiter

## Tech debt

See `tech_debt` in the frontmatter. The two items with real user impact:
- **W1:** re-evaluating `main.scd` after pressing Stop puts the transport out of sync with the GUI (one-line fix: keep `~ppPlaying` across re-evaluation).
- **W2:** no resync after an engine restart. This is accepted under the send-only v1 design.
