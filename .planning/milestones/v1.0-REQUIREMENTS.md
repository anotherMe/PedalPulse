# Requirements: PedalPulse

**Defined:** 2026-10-08
**Core Value:** Moving the BPM or EPIC control in the Python GUI audibly and smoothly changes the live music in SuperCollider — the Python → OSC → SuperCollider chain works end to end.

## v1 Requirements

Requirements for initial release (technical proof). Each maps to roadmap phases.

### Engine

- [x] **ENG-01**: When started, the engine plays drums, bass, arpeggio and pad continuously in a melodic techno / progressive trance style on a dedicated TempoClock (fixed loop patterns are acceptable for v1)
- [x] **ENG-02**: Master output never clips — a limiter on the master bus holds peaks even at maximum EPIC and volume
- [ ] **ENG-03**: User can leave the engine playing for 60+ minutes without audio dropouts and without CPU or synth node count growing (every enveloped synth frees itself)
- [x] **ENG-04**: User starts the engine from a single sclang entry file, which waits for server boot and posts the OSC port it is listening on

### Tempo

- [x] **TEMPO-01**: When the user sets a new BPM, the music glides to it over ~1–2 bars, beat-synchronously, with no audible jolt
- [x] **TEMPO-02**: When the user changes BPM while a ramp is in progress, the engine retargets smoothly from the current tempo (no restart, no jump)
- [x] **TEMPO-03**: BPM values outside 60–180 are clamped to that range by the engine

### EPIC

- [x] **EPIC-01**: EPIC level 0–100 audibly changes brightness/energy by driving filter cutoff, drive/saturation, reverb/delay amount and synth richness together
- [x] **EPIC-02**: EPIC changes glide smoothly (lagged parameters) with no stepping or clicks
- [x] **EPIC-03**: User can select EPIC via five zone preset buttons (Recovery / Endurance / Tempo / Threshold / VO2), each mapped to a predefined EPIC value

### GUI

- [x] **GUI-01**: User can set BPM via a slider, a numeric entry field, and +/- nudge buttons, all kept in sync
- [x] **GUI-02**: User can start and stop the music from the GUI
- [x] **GUI-03**: User can adjust master volume from the GUI
- [x] **GUI-04**: The Tkinter app launches on macOS with a working Tcl/Tk 8.6; on an incompatible Tk it shows a clear warning instead of failing silently

### Link

- [x] **LINK-01**: Every GUI control change reaches the engine over OSC in real time; rapid slider drags are throttled/coalesced so they don't flood the engine

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Generative Music

- **GEN-01**: Shared harmony clock — chord progression evolves over time and bass/arp/pad all follow it
- **GEN-02**: Multi-timescale variation (arp pattern changes, drum fills, swing/humanization) so a 60-minute ride never feels looped
- **GEN-03**: EPIC also drives arrangement density (layers, note density, percussion) at pattern rate

### Controls

- **CTRL-01**: EPIC fine-tune slider (continuous 0–100) alongside presets
- **CTRL-02**: User-configurable BPM ramp time (e.g. 1–8 bars)

### Automation

- **AUTO-01**: Load a workout file (.zwo) and have BPM/EPIC follow its interval timeline
- **AUTO-02**: Derive BPM from a cadence sensor (ANT+/BLE)
- **AUTO-03**: Zwift integration (if a suitable API exists)

### Styles

- **STYL-01**: Choose among multiple tracks / sub-styles

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Python app launching/managing sclang | User starts the SC patch separately; avoids process management |
| Mobile / web control UI | Tkinter desktop app on the same Mac is sufficient |
| SuperCollider quarks / third-party extensions | Stock SC classes suffice; quarks add install fragility |
| Cadence→BPM formula | User sets BPM directly by feel |
| Time-stretching pre-recorded tracks | Product is live synthesis, not playlist manipulation |
| Engine → GUI feedback: heartbeat connection indicator (was LINK-02) and live engine BPM/EPIC readout (was LINK-03) | Dropped 2026-10-10: not needed for a deliberately simple app; the Python app stays send-only |
